# 태스크 보드

`tasks/` DB 폴더 (`kind: "task_board"`). 카드 하나 = AI에게 시킬 작업 하나 = 노트 하나.

## 화면 표시

- 데이터베이스 이름은 `태스크 보드`로 고정하며 사용자가 수정할 수 없다.
- 보드와 표 보기를 모두 지원한다.
- 표에서는 작업을 빠르게 훑는 데 불필요한 `approval`, `current_run`, `priority`,
  `task_template`, 태그를 표시하지 않는다. 실행에 필요한 원본 frontmatter 값은 보존한다.
- `최근 실행`은 새 브라우저 창이 아니라 현재 앱의 Markdown 편집기 탭에서 실행 로그를 연다.

## 상태(`status`) — 유효한 값은 이 5개뿐

| value | 라벨 | 누가 바꾸는가 |
|---|---|---|
| `todo` | 📋 대기 | 사람 (카드 생성 시 기본값) |
| `running` | ⚡ 실행 중 | **시스템이 자동으로** — 직접 이 값을 쓰지 말 것 |
| `verify` | 🔎 확인 필요 | **시스템이 자동으로** (실행 정상 종료 시) |
| `blocked` | 🚫 보류 | 시스템 자동(오류·예산초과) 또는 사람 |
| `done` | 🎉 완료 | 사람 (결과 확인 후) |

카드를 새로 만들 때는 항상 `status: todo` 로 시작한다. `running`/`verify`는 실제 실행
파이프라인(orchestrator)이 실행 중에만 자동으로 붙이는 값이므로, 대화 중에 카드를
만들거나 편집하면서 이 값을 직접 써서는 안 된다 — 실제로 실행되고 있지 않은데
"실행 중"이라고 표시하면 사용자가 혼란스러워한다.

## 카드 프론트매터

```yaml
---
title: 짧은 제목
type: spec | api | ui | refactor | test | docs | other
priority: urgent | high | normal | low
status: todo
scope: (선택) 프로젝트 관리 테이블의 행 파일명(확장자 제외)
skill: [] (선택, 잘 안 씀) skill 노트 경로 목록
max_time_min: (선택) 숫자
source_session: (선택) 이 카드를 등록한 Twill AI 대화 세션 id
---

작업에 대한 자유 서술 (무엇을 해야 하는지 상세히).
```

`type`/`priority` 은 위 나열된 값만 유효하다 — 임의 문자열을 넣으면 저장이
거부된다. `scope`를 지정하면 실행 시 그 프로젝트 폴더 안에서 작업이 격리된다
(`projects-and-scopes.md` 참고). 확신이 없는 필드는 그냥 비워둬도 된다 — 필수는 `title`뿐이다.

AI 실행 승인 정책은 시스템에서 항상 허용으로 고정한다. 카드별 승인 정책이나 설정 화면에서
별도로 선택하지 않는다.

**도구 호출 횟수 한도는 프론트매터로 지정하지 않는다** — 폭주 방지용 한도는 사람이
판단하기 까다로운 값이라 시스템이 고정값으로 자동 적용한다 (카드에 `max_tool_calls`를
써도 무시된다).

## 사용자 확인과 태스크 등록

대화나 태스크를 실행하는 AI는 요청 범위 안에서 합리적으로 판단할 수 있는 구현 방식·검증·수정
사항을 스스로 처리하고, 선택적 개선이나 단순 확인 사항을 자동으로 태스크 보드에 등록하지 않는다.

사용자의 결정에 따라 결과나 범위가 실질적으로 달라지거나, 프로젝트에서 확인할 수 없는 정책
선택이나 아직 허용되지 않은 파괴적 변경처럼 결정 없이는 안전하게 진행할 수 없는 경우에는
태스크를 만들지 말고 현재 대화에서 직접 질문한다. 결정할 내용과 이유, 선택별 영향, 권장안을
설명하고 답변을 받은 뒤 같은 세션에서 작업을 이어간다.

태스크 카드는 사용자가 명시적으로 등록을 요청한 경우에만 만든다. 이전 버전이 자동 생성한
`origin: auto_followup`, `auto_created: true` 카드는 기존 기록으로 남을 수 있으며 일반 카드처럼
수정하거나 삭제할 수 있지만, 새 실행에서는 이 형식의 카드를 자동 생성하지 않는다.

현재 Twill AI 대화에서 사용자가 태스크 등록을 명시적으로 요청한 경우에는 실행 컨텍스트로 제공된
`byeori_session_id`를 카드의 `source_session`에 기록한다. 이 카드의 `Twill AI 실행`을 누르면 새
대화를 만들지 않고 해당 원본 대화를 열어, 앞서 나눈 맥락을 유지한 채 태스크를 실행한다.
원본 세션이 삭제되었거나 찾을 수 없을 때만 새 태스크 세션으로 실행한다.

## 이 매뉴얼을 읽고 있는 당신(에이전트)에게

사용자가 "이런 작업을 태스크로 만들어줘" 또는 여러 개의 작업으로 쪼개서 등록해달라고
하면, `tasks/` 아래에 위 형식의 노트를 만들면 된다. 반면 "이 태스크를 지금 실행해줘"라는
요청은 이미 실행 중인 당신 자신이 그 작업을 하라는 뜻이므로, 카드의 상태를 바꾸는 게
아니라 카드 본문에 적힌 작업 자체를 지금 수행하면 된다.
