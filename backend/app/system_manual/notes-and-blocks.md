# 노트 작성 규칙

## 프론트매터 (YAML)

모든 노트는 `.md` 파일이며 맨 위에 YAML frontmatter를 가질 수 있다.

```markdown
---
title: 제목
date: 2026-07-09
tags: [태그1, 태그2]
icon: 📄
cover: (이미지 경로, 선택)
---

본문...
```

- `title`/`date`/`tags`/`icon`/`cover` 는 예약 키. 나머지 키는 모두 `props`로 취급되어
  DB 뷰의 컬럼으로 쓰일 수 있다 (예: 태스크 카드의 `status`, `priority`).
- `title` 이 없으면 본문의 첫 `# H1` 을 제목으로 쓰거나, 없으면 파일명을 쓴다.
- 새 노트를 만들 때는 파일만 써두면 된다 — 별도 등록 API 호출이 필요 없다. 파일시스템
  워처가 감지해서 자동으로 인덱싱하고 트리에 반영한다.

## 특수 노트

- `AGENTS.md` (워크스페이스 또는 등록 프로젝트 루트) — 해당 경로가 Codex의 작업 디렉터리일 때
  Codex가 표준 탐색 규칙으로 직접 읽는 프로젝트 규약. 오케스트레이터 공통 프롬프트에는 복사하지 않는다.
- `MEMORIES.md` (워크스페이스 루트) — 앱 전체/사용자 전체에 유효한 전역 학습 사실.
  필요하면 사용자가 일반 노트처럼 직접 만들고 편집한다. `type: memories`, `auto_managed: true`
  frontmatter가 없어도 검색 원본으로 사용할 수 있다. 전체 본문은 상시 주입하지 않고 필요한 요청에서
  `search_memories`가 관련 구간만 조회한다. 프로젝트별 메모리 파일은 자동 생성하지 않는다. 앱은 일반
  대화나 태스크 결과를 자동 학습하지 않으며, 사용자가 Twill AI 채팅에서 “기억해줘”처럼 명시적으로
  요청한 사실만 이 파일에 중복 없이 기록한다.
- `type: skill` 인 노트 — 재사용 가능한 지시사항 페르소나. `name`/`aliases`/`description`
  프론트매터를 갖는다. 태스크 카드의 `skill` 컬럼에서 선택하면 본문이 자동으로 주입된다.

## 이 앱 전용 마크다운 문법 (일반 마크다운 편집기에는 없는 것들)

일반 CommonMark 문법(제목, 리스트, 인용, 코드블록, 표, 이미지, 링크 등)은 그대로 지원된다.
아래는 이 앱의 블록 에디터가 특별히 인식하는 추가 문법이다 — raw 텍스트로 이 형태를 그대로
쓰면 사용자가 에디터에서 열었을 때 전용 블록(콜아웃/토글/DB뷰 등)으로 렌더링된다.

| 만들고 싶은 것 | 정확한 문법 | 비고 |
|---|---|---|
| 콜아웃(강조 박스) | `> [!💡] 내용` | 인용 블록에 `[!이모지] ` 마커. 이모지는 원하는 것으로 |
| 토글(접기/펼치기) | `- [>] 내용` | 불릿 리스트 항목에 `[>] ` 마커 |
| 페이지 링크 | `[[상대경로 또는 노트제목]]` | 단독 문단에 이 텍스트만 있어야 함 |
| DB 뷰 임베드 | `[[db:폴더경로]]` 또는 `[[db:폴더경로\|board]]` 또는 `[[db:폴더경로\|board\|그룹컬럼]]` | 기본 모드는 table |
| Mermaid 다이어그램 | ` ```mermaid ` 코드 펜스 | 언어를 정확히 `mermaid` 로 지정 |

이 마커들을 안 쓰고 그냥 평범한 마크다운으로 써도 문제는 없다 (그냥 일반 인용/리스트/코드
블록으로 보일 뿐) — 콜아웃·토글·DB뷰처럼 이 앱 특유의 화면을 원할 때만 위 문법을 쓴다.
